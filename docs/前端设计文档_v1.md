# 前端设计文档 v1

## 1. 文档目的

本文档描述当前版本计算器系统的前端设计方案。

当前前端采用 **原生 Web 技术栈**：

- HTML：页面结构
- CSS：页面样式
- JavaScript：用户交互与 HTTP 请求

前端的主要职责是：

1. 接收用户输入；
2. 展示表达式与计算结果；
3. 向后端发送计算请求；
4. 查询、展示和删除历史记录；
5. 展示后端返回的错误信息。

前端 **不负责核心数学计算**。

---

## 2. 前端总体设计

前端整体采用 **单页面计算器界面**。

界面风格参考常见手机系统自带计算器 App，主体保持简洁，默认只显示：

- 表达式输入区；
- 结果显示区；
- 计算器按钮区；
- 左上角历史记录入口。

历史记录默认不直接占据主界面，而是在用户点击左上角 `...` 后，以侧边面板的形式打开。

---

## 3. 页面区域设计

### 3.1 表达式显示区

用于显示用户当前输入的数学表达式。

例如：

```text
1 + (2 * 3) - 5
```

第一版暂不实现实时计算预览。

用户输入表达式时，前端仅负责：

- 插入数字；
- 插入运算符；
- 插入括号；
- 插入小数点；
- 清空表达式；
- 删除字符；
- 移动光标；
- 显示当前表达式。

---

### 3.2 结果显示区

用户点击 `=` 后，前端向后端发送计算请求。

计算成功时：

```text
1 + (2 * 3) - 5
= 2
```

其中：

- 原表达式保留在上方；
- 计算结果显示在下方；
- 第一版暂不实现结果放大、表达式淡出等动画效果。

计算失败时，不使用弹窗，而直接在结果区域显示错误信息。

例如：

```text
10 / (3 - 3)
= Error: Division by Zero
```

---

### 3.3 计算器按钮区

第一版基础按钮包括：

- 数字 `0 ~ 9`
- `+`
- `-`
- `×`
- `÷`
- `(`
- `)`
- `.`
- `=`
- 清零
- 退格
- 光标移动按钮

其中：

- 数字、运算符、括号、小数点、清零、退格、光标移动均属于前端输入编辑操作；
- `=` 会触发一次后端计算请求。

---

## 4. 历史记录侧边面板

用户点击左上角 `...` 后，前端打开历史记录侧边面板。

面板设计要求：

1. 从侧边弹出；
2. 覆盖大部分计算器界面；
3. 背后的计算器界面变灰；
4. 面板打开期间，计算器主体不可操作；
5. 历史记录内容支持上下滑动；
6. 每条历史记录提供删除按钮。

示意：

```text
┌────────────────────────────┐
│ History                    │
│                            │
│ 1 + 2          = 3    删除 │
│ 4 * 5          = 20   删除 │
│ (1+2)*3        = 9    删除 │
│                            │
│       ↑ 可上下滚动 ↓       │
└────────────────────────────┘

背景：
计算器主体变灰并禁止操作
```

第一版暂不实现：

- 点击历史记录后将表达式重新填入计算器；
- 历史记录搜索；
- 历史记录分页；
- 批量删除。

---

## 5. 前端与后端通信

前端通过 HTTP API 与 C++ 后端通信。

当前第一版使用三个核心接口：

| HTTP Method | API Path | 前端用途 |
|---|---|---|
| `POST` | `/api/calculate` | 提交表达式，请求计算 |
| `GET` | `/api/history` | 获取历史记录 |
| `DELETE` | `/api/history/{id}` | 删除指定 ID 的历史记录 |

通信数据采用 JSON 格式。

---

## 6. 计算流程

用户输入：

```text
1 + (2 * 3) - 5
```

点击：

```text
=
```

前端发送：

```http
POST /api/calculate
```

请求体：

```json
{
  "expression": "1 + (2 * 3) - 5"
}
```

后端计算成功后返回：

```json
{
  "success": true,
  "result": 2
}
```

前端更新界面：

```text
1 + (2 * 3) - 5
= 2
```

---

## 7. 计算错误处理

如果后端返回计算错误，例如：

```json
{
  "success": false,
  "message": "Division by zero"
}
```

前端不弹出额外对话框，而是在结果显示区更新：

```text
10 / (3 - 3)
= Error: Division by Zero
```

这样可以避免打断用户输入流程。

---

## 8. 历史记录查询流程

用户点击左上角：

```text
...
```

前端发送：

```http
GET /api/history
```

后端返回：

```json
{
  "success": true,
  "history": [
    {
      "id": 1,
      "expression": "1+2",
      "result": 3,
      "created_at": "..."
    }
  ]
}
```

前端随后：

1. 打开历史记录侧边面板；
2. 渲染历史记录；
3. 禁用背景计算器交互。

---

## 9. 历史记录删除流程

假设用户删除：

```text
id = 17
```

前端发送：

```http
DELETE /api/history/17
```

删除成功后：

```json
{
  "success": true
}
```

前端立即再次发送：

```http
GET /api/history
```

重新获取最新历史记录并刷新侧边面板。

这样可以保证前端显示内容与数据库保持一致。

---

## 10. 前端职责边界

前端负责：

- 用户输入；
- 表达式编辑；
- 页面展示；
- 调用 HTTP API；
- 展示后端返回结果；
- 展示错误；
- 展示与刷新历史记录。

前端不负责：

- 数学表达式解析；
- 运算符优先级判断；
- 四则运算求值；
- 除零判断；
- 历史记录持久化。

核心计算必须由后端完成。

---

## 11. 当前暂不实现的功能

当前版本暂不实现：

- 实时计算预览；
- 表达式淡出动画；
- 结果放大动画；
- 点击历史记录重新载入表达式；
- 批量删除历史记录；
- 搜索和分页；
- 科学计算；
- 单位换算；
- 用户系统；
- 主题切换。

这些功能可以在基础版本完成后继续迭代。

---

## 12. 当前前端设计结论

第一版前端确定为：

> **手机计算器式单页面 Web 界面 + 点击等号后请求后端计算 + 侧边历史记录面板。**

其核心目标是先完成稳定、清晰的基础交互，再在后续版本中加入实时预览和动画效果。
